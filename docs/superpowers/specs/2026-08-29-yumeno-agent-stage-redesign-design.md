# YUMENO 展示站「Agent 舞台」重构设计说明

日期：2026-08-29
状态：已获用户确认，等待书面规格复核

## 1. 目标

将当前独立展示页重构为一个简约、沉浸、可快速理解的 YUMENO 产品展示站。核心叙事从“角色 AI 工具集合”调整为：

> 一个由 Supervisor 统筹、多个受限 Agent 协作完成角色体验的本地工作台。

展示站不承担 YUMENO 主应用的运行功能，只负责展示产品定位、真实素材、Agent 协作方式和站内详细文档，并提供主项目源码与 Release 下载入口。

## 2. 已确认的产品事实

以下内容来自本地 YUMENO 的 README、PRODUCT、ARCHITECTURE、docs 与相关实现梳理：

- YUMENO 面向 Windows 本地优先使用，不要求注册和登录。
- 角色拥有独立的人设、会话、记忆与知识空间。
- `persona_supervisor` 负责路径选择、上下文统筹和最终表达。
- knowledge 采用 Planner + 确定性检索 / SQL / web 管线；不是多个 Agent 无限制自由对话。
- memory、document、profile、voice_clone、config 等领域由受限 Worker 处理。
- 领域 Worker 的结果通过 `finalize_*` 合同回到 Supervisor。
- 写入、修改、训练等敏感操作支持 HITL / checkpoint。
- RAG 使用 Dense + BM25 + RRF；CSV/XLSX 进入隔离 SQLite；Milvus 用于向量知识持久化。
- 声音工坊支持素材提取、人声分离、切片、选择、拼接、试听、保存和角色绑定。
- 展示页已有 Mortis 角色视觉与两段真实音频素材。

## 3. 页面信息架构

主展示页使用全屏章节舞台，章节通过 URL hash 定位：

```text
#home       极简首页
#operator   角色展台与 Agent 入口
#voice      声音工坊与真实音频
#agents     角色化 Agent 系统地图
#docs       文档入口
```

详细文档使用独立页面：

```text
/docs.html
```

文档页使用普通滚动和站内锚点，不把长文硬塞入全屏场景动画。

## 4. 核心交互设计

### 4.1 全屏章节切换

- 页面主体固定为 `100svh` 视口。
- 章节容器使用 `transform: translate3d(0, -N*100svh, 0)` 切换。
- 滚轮、触摸滑动、键盘上下键和章节导航均可切换。
- 每次操作只移动一个章节，避免滚轮惯性跳过多个场景。
- 使用 700ms 左右的 cubic-bezier 缓动；用户开启 reduced motion 时关闭位移动画，保留即时定位。
- `hashchange`、前进/后退和首次加载 hash 均能正确同步章节。
- 章节导航高亮当前场景，并显示当前章节进度。
- 页面顶部提供很短的章节名称，避免装饰性编号和无意义的小字。

### 4.2 首页

首页只承担定位和入口：

- YUMENO 品牌标识；
- 一句通俗、短的产品说明；
- “进入系统”按钮；
- 一个弱化的章节导航提示。

首页不放技术指标、不放大段说明、不放随机动态背景、不放大尺寸 Live2D。

### 4.3 `#operator`：角色与 Agent 入口

角色展示板块以 Mortis 的真实视觉为主，控制在右侧较小区域。左侧用一句话解释角色体验如何由多个 Agent 支撑：

```text
一个角色，不只拥有回答。
它还有记忆、知识、声音，以及可以被确认的行动。
```

显示一个简洁的协作脉络：

```text
角色对话 → Supervisor → 记忆 / 知识 / 声音 / 工具
```

可以提供“待机 / 思考 / 回应”三个固定状态按钮。由于现有素材未确认存在完整动作 motion 资源，第一版只实现可信的状态反馈（文案、光线、轮廓和轻微位移），不宣称为真实 Live2D 动作。

### 4.4 `#voice`：真实声音

展示两段真实本地音频，并提供：

- 播放/暂停；
- 进度拖动；
- 当前播放时间；
- 清晰的素材来源说明；
- 声音工坊流程线：素材 → 分离 → 切片 → 拼接 → 试听 → 绑定。

波形只作为静态或由真实播放进度驱动的细线，不使用与音频无关的假动画。

### 4.5 `#agents`：角色化 Agent 系统核心舞台

这是整站最重要的章节，不再把多 Agent 作为角落中的架构卡片，而是把它作为 YUMENO 的主要产品叙事。

中央节点：

```text
PERSONA SUPERVISOR
```

周围节点：

- KNOWLEDGE PLANNER：检索、RAG、SQL、web；
- MEMORY WORKER：整理长期记忆；
- DOCUMENT WORKER：导入和处理资料；
- PROFILE WORKER：角色档案和设定；
- VOICE CLONE WORKER：参考音频与声音；
- CONFIG WORKER：Provider 与运行配置。

视觉采用可读的线路式系统地图：

- 青蓝色表示主控制流；
- 紫色表示知识与推理线路；
- 粉色只用于少量人工确认 / checkpoint 标记；
- 不使用随机节点漂移；
- 不使用夸张的 3D 科技球；
- 线路动画只表示数据流方向，且可被 reduced motion 禁用。

同时明确表达：

1. Supervisor 负责理解意图、选择路径并统一表达；
2. Worker 只处理受限领域任务；
3. 领域结果必须通过 `finalize_*` 回到 Supervisor；
4. 敏感写入与训练可以暂停等待人工确认；
5. 这是一套可追踪、可恢复的协作系统，而非无限并行的 Agent 聊天。

### 4.6 `#docs`

主站只展示文档入口、主题列表和“打开完整文档”按钮，跳转到 `/docs.html`。不使用抽屉承载完整技术文档。

## 5. 视觉系统

### 5.1 颜色

- 背景：黑色、近黑灰；
- 内容：白色、冷灰；
- 主强调：青蓝色；
- 辅助线条：深蓝灰；
- 紫色、粉色：仅用于线条端点、状态、人工确认提示或局部渐变；
- 禁止上一版的暖白、朱红和大面积暖色。

### 5.2 形态

- 细边框、线路、切角和网格；
- 大留白；
- 少量大字号标题；
- 真实图片和音频承担主要视觉内容；
- 不使用“01 / 里面如何工作”一类装饰性眉题；
- 不使用大量圆角卡片堆叠；
- 不使用无法解释的随机动态背景。

### 5.3 动画

动画集中在三类：

1. 章节整体切换；
2. 内容随场景进入；
3. Agent 线路和当前节点状态反馈。

所有动画均须支持 `prefers-reduced-motion`。

## 6. 独立文档页内容

`docs.html` 包含左侧目录（移动端改为顶部选择/折叠目录）和右侧正文：

- 快速开始；
- 系统要求；
- Windows 安装；
- Provider 与模型配置；
- 角色、会话与记忆；
- 知识空间、RAG、表格查询；
- 多 Agent 架构；
- 声音工坊；
- Live2D；
- Skill、MCP 与工具；
- HITL / checkpoint；
- 部署与外部接入；
- 数据目录与隐私；
- 常见问题。

文档中对“当前实现”和“可选能力”做清晰区分，避免把规划能力写成已完成事实。

## 7. 响应式要求

### 桌面端

- 维持完整全屏场景；
- 左侧导航、右侧内容与线路图同时展示；
- 角色图小尺寸但清晰；
- Agent 系统地图可显示完整节点关系。

### 移动端

- 章节仍按一屏一场景切换；
- 线路图改为纵向堆叠，保证文字可读；
- 角色图降低尺寸并避免遮挡；
- 音频卡片改为单列；
- 文档页取消固定侧栏，改用顶部目录。

## 8. 内容与链接边界

展示页只保留：

- 主项目 GitHub 源码链接；
- GitHub Releases 下载链接；
- 本站内部 `/docs.html` 文档链接。

不使用 GitHub Pages。部署目标是用户已有域名和服务器，最终产物为 Vite `dist/` 静态文件。

## 9. 验收标准

- 首页在第一屏内能够说明 YUMENO 是什么，并且没有技术堆砌；
- 鼠标滚轮、键盘、hash 导航和移动触摸能稳定切换章节并自动对齐；
- 多 Agent 系统是最醒目的核心章节，而不是普通卡片；
- Supervisor、Worker、finalize 合同和人工确认关系表达准确；
- 真实 Mortis 素材和两段本地音频可以正常显示/播放；
- 不再依赖旧的 Peel、Ascii Sweep 等不符合当前方向的动态效果；
- 文档通过 `/docs.html` 独立访问，内容覆盖系统、架构、使用、FAQ、部署和要求；
- 桌面端和移动端无明显溢出、遮挡或无法操作的章节；
- `npm run build` 通过；
- 本地服务可在 `http://127.0.0.1:17000/` 访问；
- 产物可以直接上传到已有服务器，不依赖 GitHub Pages。
