## 1. 背景与问题

当前页面已完成一次视觉重做，但用户反馈了三个根本问题：

1. 配色偏纸张、朱红和海报感，不像现代的本地角色工作台。
2. Peel 被放在首页主视觉中，只揭开一块宣传卡片，缺少实际功能含义。
3. 声音区域只有 CSS 柱状波形，没有用户触发的播放状态、暂停状态、进度变化或真实的交互反馈。

另外，部署方式不应作为独立的大型页面板块，而应压缩为工作台中的一个轻量选择器。

## 2. 设计目标

- 让首次访问者先理解 YUMENO 是一个可以长期使用的角色工作台。
- 让 Peel 服务于实用导航，而不是承担装饰性宣传。
- 让声音演示产生明确、可感知且由用户触发的反馈。
- 让 ASCII Sweep 用于有意义的内容切换，而不是持续覆盖页面的背景动画。
- 用现代、克制的浅色界面替代上一版纸张与朱红主导的风格。
- 保持独立静态站点的部署方式：构建 `dist/`，由用户上传到自己的服务器；不增加 GitHub Pages 流程。

## 3. 非目标

- 不在展示站中实现 YUMENO 主项目完整聊天功能。
- 不把浏览器合成试听音描述为 YUMENO 已提供的真实角色配音。
- 不引入登录、后端、数据库或第三方统计服务。
- 不新增独立的“部署方式”大型章节。
- 不使用自动播放音频。

## 4. 整体页面结构

### 4.1 Hero：角色工作台

Hero 主视觉由产品工作台 mockup 组成，包含：

- 当前角色名称与状态
- 简化对话内容
- 最近记忆摘要
- 知识空间状态
- 声音绑定状态
- 本地工作区状态

文案保持通俗，不在标题和副标题中堆叠技术术语。页面标题强调“角色逐渐成为熟悉的存在”，副标题解释创建角色、声音、记忆和资料空间的关系。

### 4.2 Peel：工作台侧边工具栏

Peel 放在 Hero 工作台的左侧边缘：

- 默认只显示窄侧边标记。
- 光标接近左侧边缘时，侧边栏逐步展开。
- 下层内容是可交互的导航和状态面板。
- 导航项目包括：当前角色、角色、记忆、知识空间、声音工坊、设置。
- 面板底部显示“本地工作区、资料已隔离、无需注册”等状态。
- 支持键盘聚焦和退出聚焦。
- 移动端使用固定按钮点击展开，不依赖 hover。
- `PeelReveal` 的公开接口改为侧边栏语义，避免继续把它作为 Hero 宣传卡片使用。

### 4.3 ASCII Sweep：工作台状态切换

ASCII Sweep 只用于内容在不同状态面板之间的切换。第一处切换包含：

- 角色状态
- 声音状态
- 记忆状态

切换流程：

1. 用户点击 tab 或使用键盘切换。
2. 当前面板与目标面板进入 ASCII 字符扫过动画。
3. 动画结束后目标内容成为当前内容。
4. 不支持相关 Canvas 能力时，使用渐变扫光和普通内容切换作为降级。

组件应支持受控的 `index` 或等价的目标面板状态，并且只有切换发生时触发一次动画，不应默认无限循环。

### 4.4 声音工坊：可交互试听

声音工坊保留为主要展示区域，但改为真实的交互状态：

- 点击播放按钮后，由浏览器 `Web Audio API` 生成一段短暂、克制的试听提示音。
- 明确标注这是浏览器中的视觉/声音演示，不代表内置真实角色音频文件。
- 播放状态显示暂停按钮、进度变化和“试听中”状态。
- 波形通过 `requestAnimationFrame` 根据播放状态动态变化。
- 未播放时保持低幅度呼吸，播放时提升振幅并改变颜色/进度。
- 播放结束后回到等待试听状态。
- 允许用户暂停，不允许自动播放。
- 提供 `prefers-reduced-motion` 降级：保留状态与进度，不使用明显的连续运动。

声音流程步骤为：

```text
素材 → 处理 → 试听 → 绑定
```

点击步骤时，当前步骤、说明和状态标签同步变化。

### 4.5 本地工作方式：嵌入式部署选择器

删除独立的大型部署章节。在本地工作方式区域中加入紧凑选择器：

```text
快速体验 | 混合使用 | 完全本地
```

选择不同选项时替换一段简短说明：

- 快速体验：先感受角色对话和知识能力。
- 混合使用：对话连接服务，声音、资料和角色数据保留在设备上。
- 完全本地：模型、声音、资料和会话都在本地运行。

该选择器可复用 ASCII Sweep 或轻量内容过渡，但不再形成新的大板块。

### 4.6 其余章节

保留并压缩以下内容：

- 角色、声音、记忆、知识、行动的体验说明。
- 本地隔离、敏感操作确认和资料边界。
- 项目内部评测数据，并继续标注“项目当前资料中的内部评测数据，不代表第三方认证”。
- 下载、Releases、源码和文档入口。

## 5. 视觉系统

### 颜色令牌（初始方向）

```text
--bg: #F6F7F9
--surface: #FFFFFF
--surface-muted: #EEF1F5
--ink: #1E2430
--muted: #6D7685
--primary: #5657D9
--primary-deep: #3F40A7
--accent: #21B8A6
--border: #E1E5EB
--warning: #E3A33B
```

要求：

- 不再使用大面积朱红作为主色。
- 主色用于交互、选中状态和关键 CTA。
- 青绿色用于“本地、已连接、正在播放”等积极状态。
- 文字、边框和背景需要满足基本可读性。
- 响应式布局保持桌面和移动端一致的层级关系。

## 6. 交互与可访问性

- 所有交互控件使用真实的 button/link 语义。
- Peel 导航支持键盘聚焦、Enter/Space 展开和 Escape 关闭。
- tab 支持键盘切换，并提供 `aria-selected` 与对应面板关系。
- 声音播放必须由用户操作触发。
- 对 `prefers-reduced-motion` 提供降级。
- 视觉反馈不能是唯一的信息来源，状态需要有文字标签。

## 7. 验收标准

### 视觉

- 页面整体不再以纸张、朱红为主视觉。
- Hero 清楚展示角色工作台，而不是一张被揭开的宣传海报。
- Peel 视觉上位于侧边，并且下层内容是导航/状态面板。
- 部署方式只作为嵌入式选择器出现。

### 交互

- 桌面端鼠标靠近侧边时 Peel 展开，离开后收起或保持可操作状态。
- 移动端可以点击按钮打开 Peel。
- 角色/声音/记忆 tab 切换时触发 ASCII Sweep 或可感知的降级过渡。
- 点击声音试听后能听到浏览器生成的短音效，同时波形、进度和状态发生变化。
- 点击暂停后声音停止，波形回落。
- 关闭动画偏好后页面仍可用。

### 工程

- `npm run build` 成功。
- 不依赖 GitHub Pages。
- 不新增后端服务。
- 关键逻辑集中在可维护的 React 组件中。
- 页面可通过 `dist/` 部署到用户自己的服务器。

## 8. 风险与处理

- **浏览器音频策略**：使用用户点击启动 `AudioContext`，不自动播放。
- **Canvas/HTML-in-Canvas 支持差异**：ASCII Sweep 必须提供 CSS/DOM 降级。
- **过度动效**：限制为 tab 切换、侧边 Peel 和声音状态反馈，并支持减少动效。
- **浏览器合成音与真实声音的误解**：界面明确标注演示性质，不宣称使用真实角色音源。
